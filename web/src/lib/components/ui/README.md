# shadcn-svelte components (SPEC-24)

**Icons are Hugeicons, never lucide.** Use `HugeiconsIcon` from `@hugeicons/svelte` with an icon from `@hugeicons/core-free-icons`. Do not add `@lucide/svelte` as a dependency. `components.json` sets `"iconLibrary": "hugeicons"`, so `npx shadcn-svelte@latest add <name>` normally writes Hugeicons already. If a component still imports lucide, swap in the Hugeicons equivalent before you commit it.

Everything in this directory is generated by `npx shadcn-svelte@latest add <name>` (style `mira`, base color `neutral`) and then adapted to the rules below. Run the CLI from `web/`.

## Rules for every component added here

1. **Tokens are `--ui-*`.** The shadcn variables live in `src/ui.css` under the `--ui-` prefix (`--ui-background`, `--ui-border`, `--ui-radius`, ...), because `app.css` already owns `--border` and `--radius` and older components read `--accent`, `--chart-1..4` and `--sidebar-width` with other meanings. Tailwind classes (`bg-background`, `border-border`, `rounded-md`) need no change. A raw reference in an arbitrary value does: rewrite `var(--secondary)` to `var(--ui-secondary)`, and `bg-(--sidebar)` to `bg-(--ui-sidebar)`. `uiTokens.test.ts` fails on a reference it does not recognise.
2. **Do not let the CLI edit CSS.** Some components (sidebar, chart) ship CSS variables, and `add` writes them unprefixed into `src/ui.css`. Revert that hunk and add the `--ui-` versions by hand, in both light blocks.
3. **There is no Preflight yet** (TASK-32 turns it on). `src/ui.css` scopes the two reset rules the Button needs to `[data-slot]` elements. Check a new component in `/_ui-preview` before relying on a browser default.
4. **Only scanned paths get utilities.** `src/ui.css` sets `source(none)` and lists `@source` paths. A new directory that uses Tailwind classes needs its own `@source` line. Every utility generated is global, so a class name that legacy markup also uses (`grid` is one: the insights and tutorials pages use it) applies there too. Check new utility names against the old markup before you add a path.
5. **The `dark:` variant follows `data-theme`** on `<html>`, as the rest of the app does. Don't add a `.dark` class.

The CLI cannot read SvelteKit 3's `"extends": "$app/tsconfig"`. To run it, point `extends` at `./node_modules/$app/tsconfig.json` in `web/tsconfig.json` for the run (after `npx svelte-kit sync`), then revert the change.

## Buttons (TASK-26)

Measured from Linear (dark): buttons almost never have a box.

| Use | `variant` / `size` | Look |
| --- | --- | --- |
| Text action ("+ New task", "Add label", "Cancel", "Load more"), the default for anything that is not the primary submit | `ghost` | No fill, no border, 13px medium text in `--ui-muted-foreground`; on hover the text goes to `--ui-foreground` over a +4% white fill, radius 6px |
| Icon-only button (filter, copy link, panel toggle) | `icon` with `size="icon"` | A 28px circle filled with `--ui-tab`, a rim about 7% white, a 14px muted icon. A split button (icon + chevron) is the same pill with both inside |
| The main submit of a form or dialog (Create, Save, Confirm) | `default` | Indigo `--ui-primary`. Not for header actions such as "New task": those are text actions |
| A destructive action | `destructive` | Red text action |
| The final confirm of an irreversible action (the Alert Dialog's confirm) | `destructive-solid` | Filled red |
| The selected state of a toggle group | `secondary` | A subtle filled pill |
| Not for actions | `outline` | A bordered box reads as an input in this theme |

Legacy `common/Button` mapping, as applied: `primary` became `default` only where it is a form or dialog submit and `ghost` elsewhere (header and empty-state actions); `secondary`, the default, and `ghost` became `ghost`; `danger` became `destructive`; `danger-solid` became `destructive-solid`. Sizes: legacy `md` is `default` (28px), `sm` is `sm`.
