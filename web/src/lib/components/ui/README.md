# shadcn-svelte components (SPEC-24)

**Icons are Hugeicons, never lucide.** Use `HugeiconsIcon` from `@hugeicons/svelte` with an icon from `@hugeicons/core-free-icons`. Do not add `@lucide/svelte` as a dependency. `components.json` sets `"iconLibrary": "hugeicons"`, so `npx shadcn-svelte@latest add <name>` normally writes Hugeicons already. If a component still imports lucide, swap in the Hugeicons equivalent before you commit it.

Everything in this directory is generated by `npx shadcn-svelte@latest add <name>` (style `mira`, base color `neutral`) and then adapted to the rules below. Run the CLI from `web/`.

## Rules for every component added here

1. **Tokens are `--ui-*`.** The shadcn variables live in `src/ui.css` under the `--ui-` prefix (`--ui-background`, `--ui-border`, `--ui-radius`, ...), because `app.css` already owns `--border` and `--radius` and older components read `--accent`, `--chart-1..4` and `--sidebar-width` with other meanings. Tailwind classes (`bg-background`, `border-border`, `rounded-md`) need no change. A raw reference in an arbitrary value does: rewrite `var(--secondary)` to `var(--ui-secondary)`, and `bg-(--sidebar)` to `bg-(--ui-sidebar)`. `uiTokens.test.ts` fails on a reference it does not recognise.
2. **Do not let the CLI edit CSS.** Some components (sidebar, chart) ship CSS variables, and `add` writes them unprefixed into `src/ui.css`. Revert that hunk and add the `--ui-` versions by hand, in both light blocks.
3. **There is no Preflight yet** (TASK-32 turns it on). `src/ui.css` scopes the two reset rules the Button needs to `[data-slot]` elements. Check a new component in `/_ui-preview` before relying on a browser default.
4. **Only scanned paths get utilities.** `src/ui.css` sets `source(none)` and lists `@source` paths. A new directory that uses Tailwind classes needs its own `@source` line. Every utility generated is global, so a class name that legacy markup also uses (`grid` is one: the insights and tutorials pages use it) applies there too. Check new utility names against the old markup before you add a path.
5. **The `dark:` variant follows `data-theme`** on `<html>`, as the rest of the app does. Don't add a `.dark` class.

The CLI cannot read SvelteKit 3's `"extends": "$app/tsconfig"`. To run it, point `extends` at `./node_modules/$app/tsconfig.json` in `web/tsconfig.json` for the run (after `npx svelte-kit sync`), then revert the change.

## Buttons (TASK-26)

Measured from Linear (dark): buttons almost never have a box.

| Use | `variant` / `size` | Look |
| --- | --- | --- |
| Text action ("+ New task", "Add label", "Cancel", "Load more"), the default for anything that is not the primary submit | `ghost` | No fill, no border, 13px medium text in `--ui-muted-foreground`; on hover the text goes to `--ui-foreground` over a +4% white fill, radius 6px |
| Icon-only button (filter, copy link, panel toggle) | `icon` with `size="icon"` | A 28px circle filled with `--ui-tab`, a rim about 7% white, a 14px muted icon. A split button (icon + chevron) is the same pill with both inside |
| The main submit of a form or dialog (Create, Save, Confirm) | `default` | Indigo `--ui-primary`. Not for header actions such as "New task": those are text actions |
| A destructive action | `destructive` | Red text action |
| The final confirm of an irreversible action (the Alert Dialog's confirm) | `destructive-solid` | Filled red |
| The selected state of a toggle group | `secondary` | A subtle filled pill |
| Not for actions | `outline` | A bordered box reads as an input in this theme |

Legacy `common/Button` mapping, as applied: `primary` became `default` only where it is a form or dialog submit and `ghost` elsewhere (header and empty-state actions); `secondary`, the default, and `ghost` became `ghost`; `danger` became `destructive`; `danger-solid` became `destructive-solid`. Sizes: legacy `md` is `default` (28px), `sm` is `sm`.

## App adapters (`$lib/components/ui-adapters/`, TASK-26)

Some legacy primitives carried app behaviour the stock components do not, and the call sites and their tests depend on it. Those live in one adapter each, composed from the components here; `ui.css` scans the folder (`@source`).

- **AppDialog** (replaces `common/Modal`): Dialog with the parent's `open` as the single source of truth (Escape and backdrop presses call `onclose()`, so a draft guard can refuse), the BUG-3229 full-press backdrop rule, `maxWidth` / `placement` / `closeOnBackdrop` / `labelledby`. Mounted only while open: bits-ui's Presence ignores the first change of `open` after it is constructed.
- **ResponsiveMenu / ResponsiveMenuItem** (replace `common/Menu` / `MenuItem`): Dropdown Menu on desktop, the existing BottomSheet at the mobile breakpoint with `sheetOnMobile`. Keeps the old keyboard model (first-row focus, wrapping arrows over every `menuitem`, Escape refocuses the trigger, no typeahead), the escape stack, and the portal scroll dismissal.
- **AppToaster / AppToast** (replace `common/ToastContainer`): mirrors `toastStore` into Sonner; the store keeps timing, holds, grouping and history.

`ConfirmDialog` is the Alert Dialog host for the `confirmDialog` store.

Two more rules learned here:

- **bits-ui and svelte-sonner compile in runes mode** (`svelteCompileOptions.ts`). A few of their files use no rune, and one legacy-mode component switches the whole Svelte runtime into legacy mode.
- **Check the built CSS for collisions** before you add an `@source` line or prose to a scanned file: every word becomes a candidate, and a generated utility (`.grid`, `.inline`, `.table`, `.block`, `.visible`) hits any legacy element with that class. Reword the prose, or rename the legacy class.

## Sidebar and Breadcrumb (TASK-27)

The desktop sidebar (`layout/SidebarDesktop.svelte`) and the content panel's header (`layout/PanelHeader.svelte`) are built on these. What was changed from the CLI's output:

- **Widths are tokens.** shadcn's `--sidebar-width` / `--sidebar-width-icon` are `--ui-sidebar-width` (241px, Linear's) and `--ui-sidebar-width-icon` in `ui.css`'s `:root`, the same in both themes like `--ui-radius`. app.css keeps `--sidebar-width` for the mobile drawer.
- **The app owns the state.** No cookie and no Mod+B shortcut in the provider (Mod+B is bold in the editor; Mod+\ already toggles the chrome); `open` comes from `uiStore`. `isMobile` reads the app's breakpoint store, and `Sidebar.Root` has no mobile Sheet branch: below the breakpoint the sidebar is the app's own drawer.
- **Dropped:** `input`, `skeleton`, `sheet`, and the sidebar's `Input`, `MenuSkeleton`, `Rail` and `Trigger`, which nothing uses (the skeleton also reads a non-token variable).
- **`data-active` is absent, not `"false"`,** when a menu button is inactive: `data-active:` matches the attribute's presence.
- **Linear's row:** `MenuButton` is 28px, 13px medium, hover +4% white, active filled `--ui-sidebar-accent`, radius 6px; `MenuBadge` is the gray right-aligned count; `GroupLabel` the 12px gray section header.
- **Lists need `list-none`** while there is no Preflight: the breadcrumb's `<ol>` showed "1." markers.

Unwanted candidates can be excluded in `ui.css` with `@source not inline("word")` when a scanned file has to contain the word (PanelHeader passes NotificationPanel a `visible` prop).

## Popover and Command (TASK-30)

`popover` and `command` are the shadcn components restyled to Linear: the Popover is a hairline-bordered `--ui-popover` surface at z-400 (the Dropdown Menu's layer), the Command's search row is borderless with a hairline under it (a search glyph only with `showIcon`), and a row is 32px / 13px with a highlight of the foreground at 5% (so +5% white in dark). The CLI also pulled `input-group`, `input` and `textarea` for the search field; they are dropped, and `Command.Input` renders a bare input. `command-item` has no built-in check: a picker draws its own.

- **AnchoredPopover** (`ui-adapters/`) is the Popover the pickers share: controlled `open`, the consumer's own trigger as anchor (exempt from outside presses so its click toggles), the dialog portal target, the escape stack, focus to the search on open and back to the trigger on Escape or a choice (`close(true)`, after the panel unmounts, because its focus trap would take it back).
- **Filtering is ours** (`shouldFilter={false}`) wherever the rows are numbered or searched by more than their label (StatusPicker, EmojiPickerPanel). `columns={6}` gives the icon grid its four-arrow navigation.
- **jsdom** needs `Element.prototype.scrollIntoView`, which Command calls when the highlight moves; `src/test/setup-jsdom.ts` stubs it.
- The **command palette** (`search/CommandPalette.svelte`) is NOT built on bits-ui Command: its combobox ARIA, focus return, covered-page handling and docked mobile sheet are its own and are pinned by tests. It takes the same tokens and Linear's measurements in its scoped CSS.

## Inputs and the table (TASK-31)

- **Form controls.** `input`, `textarea`, `native-select` (a real `<select>`: Pad's callers bind plain options, and native keeps the OS picker on mobile), `checkbox`, `switch` and `label`. A field is 32px, 13px text (16px under 768px so iOS does not zoom), `--ui-input` border, 6px radius, and a 2px `--ui-ring` OUTLINE on keyboard focus (an outline, not a box-shadow ring: `task-2262` measures `outline-width`). The bits `ref` is `$bindable()` with no fallback, so a call site may bind a `$state()` that starts undefined.
- **Legacy field rules.** app.css's global `input/textarea/select` focus rules skip any element with a `data-slot`. A call site cannot pass Tailwind classes unless its file is an `@source`, so layout goes in `style=` (`wrapperStyle` on NativeSelect, whose `class` and `style` would otherwise land on the wrapper and the select) or in a `:global(.hook)` rule in the parent. Keep the old class as a plain hook when a test or e2e spec selects by it.
- **Autofocus.** A component takes no `use:` action: use `{@attach autofocusOn()}` (`$lib/a11y/autofocus`).
- **`ui/table` is not installed.** The table view is a CSS grid of `role=table` divs on purpose (TASK-1348, TASK-2208: `content-visibility` and subgrid are no-ops on `<tr>`/`<td>`), and the shadcn primitives render real table boxes. `TableView` keeps its grid, sort, columns and keyboard logic and takes the Data Table's look: 38px rows, a 12px gray header, 1px dividers, +4% hover, StatusIcon/PriorityIcon cells.

## The item page (TASK-31, part B)

`items/ItemDetail.svelte` is Linear's issue page: a grid (`.item-layout` is its query container, `.item-grid` the grid) of the **head** (title, then a gray meta line "REF · created · updated · synced"), the **properties** column (272px, no card, no separators) and the **main** column (text tabs with an indigo underline, the Tiptap body, comments).

- **Two columns by container width, not viewport.** At `.item-layout` ≥ 860px the head and main sit in a 720px reading column and the properties beside them; below it, and in the docked pane whatever the screen, the grid stacks: toolbar, head, properties (the collection's `layout` setting still shapes that compact block), main. `e2e/task-2209-balanced-fields-pane.spec.ts` measures both. Do not give `.item-layout` `contain`, `transform` or `filter`: the mobile BottomSheet is `position: fixed` inside it.
- **Toolbar** (`.meta-actions`): round 28px buttons, copy link (`ItemLinkCopyButton`), copy ref, star, apps, ⚡, counts, ⋯. It is the top right of the wide page and the top left of the stacked one (BUG-2610: the menus open towards the pane). The `.tool-btn` look is the Button's `icon` variant, written in ItemDetail because the ⋯ and star triggers are `bind:this` elements it owns.
- **No breadcrumb on desktop.** The panel header shows workspace › collection › REF; the mobile chrome has none, so `viewport.isMobile` keeps the page's own.
- **Properties.** A row is a gray 13px label and a value that is a borderless text action. Status and priority are `StatusPicker appearance="row"`; every other field is `FieldEditor appearance="property"`: a select or multi_select is `fields/PropertyPicker` (Popover + Command, `AnchoredPopover`), the assignee and role use it too (with an avatar and "People" / "Agents" groups), and dates, numbers, text and links read as text until focused. `appearance="form"` (the default) is the boxed control the copy dialog uses.
- **Summary** (the TASK-22 card for handing an item to an agent) stays above the body, restyled as a borderless gray block. Its full-width text is what the narrow properties column cannot show.
- **Sub-issues stay on the Relationships tab**, where about ten e2e specs address them; only their look moved (no divider, a gray "+ Add child").
